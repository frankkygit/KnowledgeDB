# 笔记记录与在线编辑方案

日期：2026-10-21。状态：设计已获认可；本地 Git 适配器和浏览器 GitHub docs 写入适配器已实现，真实令牌、分支保护和线上数据行为仍待用户验证。当前实现边界见 [笔记工作区与离线预览](offline-note-preview.md)。总体范围是 Blog 阅读记录、个人 Markdown 笔记及网页端 Git 保存；延续 GitHub Pages + 浏览器直连私有 docs/comments 库，不新增业务服务。

## 1. 统一的 Markdown 笔记，两种创建来源

笔记的核心对象是一篇可在线创建、阅读、编辑、更新并提交到 Git 的 Markdown 文档。Blog 阅读和个人笔记只在创建入口与来源元数据上不同，共用列表、正文模型、编辑器、附件、版本、搜索和保存管线。来源类别表示笔记从何而来，不限制后续由谁编辑。

| 来源 | 主要内容 | 生产方式 | 默认状态 |
| --- | --- | --- | --- |
| Blog 阅读记录 | 原始出处、中文概述、必要配图，可继续补充自己的理解 | 用户在 Codex 提供 URL，Agent 实际读取后整理 | draft，待核对 |
| 个人笔记 | 用户自己的 Markdown、附件及参考链接 | 网页新建、编辑、预览、提交 | 用户选择 draft 或 published |

两种笔记直接平铺在左侧“笔记”列表下，每篇笔记占一项，不按来源建立文件夹或父子层级。列表展示中文标题、来源类别标签、用户 tags 和更新时间；Blog 另显示原站点名称。默认按更新时间倒序，更新后重新排序。延续左右独立滚动与手机抽屉。

列表上方显示筛选条件区：来源（全部 / Blog 阅读 / 个人笔记）、tags（多选，任意一个匹配）、状态（全部 / 草稿 / 正式）以及全文搜索。来源、状态、搜索条件彼此取交集；标签组内部取并集，再与其他筛选相交。显示已选条件、结果数量和“清除筛选”。来源是固定元数据，tags 是用户自定义主题标签，两者不互相代替。默认显示全部来源的正式笔记，草稿可通过状态筛选查看；过滤后的搜索仍打开实际命中的笔记与段落。

点击任何笔记，右侧直接显示这篇 Markdown 正文和“编辑”按钮。Blog 额外展示“原文：标题 / 作者 / 站点 / 原始链接 / 访问日期”出处卡片；个人笔记可自愿填写参考资料。Blog 没有额外的“我的笔记”子入口，用户可直接在同一篇正文中增加个人理解，并与原文观点、Agent 分析明确区分。独立笔记可通过文档 ID 关联论文或专题。

统一流程：创建初稿（Codex 整理 Blog / 网页新建个人笔记）→ 平铺列表 → 阅读 → 在线编辑 → 预览差异 → 保存并提交 → 显示更新后的正文和时间。

## 2. Blog 阅读流程与来源

第一版在 Codex 中由用户手动提供链接，调用已有本地 kb-note-ingest 流程。Pages 本身不运行 Agent，也不持有模型密钥；网页上的自动抓取和生成按钮不进入第一版。跨站正文抓取可能受访问控制及浏览器跨域限制，不能承诺网页粘贴任意 URL 后直接生成。

流程：提供 URL → 实际读取正文及关键图 → URL 查重 → 生成中文概述草稿 → 核对 → 提交私库 → 同步阅读器版本。无法读取时报告原因，允许用户提供正文；不得根据标题猜测概述。页面中引用的其他文章仅作为引用，不自动扩展抓取范围；页面内容属于资料，不能作为 Agent 的操作指令。

中文概述建议包含：

1. 一句话总结与适用场景。
2. 原文核心观点、方法或步骤。
3. 必要的示例、代码和关键图说明。
4. 原文自身提到的限制。
5. 单独标识的 Agent 分析、待核对项。
6. 原始出处和引用清单。

标题、概述和图注以中文展示，原文标题、作者名、专有名词、代码保留原貌。原文结论、Agent 推断和用户判断分别标识；未执行的实验不写成已验证结果。

来源保存 submittedUrl、canonicalUrl、originalTitle、author、siteName、sourceLanguage、publishedAt、accessedAt。保留用户输入链接及实际页面最终链接；规范化仅删除确认属于跟踪用途的参数。作者、发布日期等未知字段留空并显示待核对，不推断补齐。按 canonicalUrl 提醒重复，用户可选择打开旧记录或生成更新候选。

概述以自己的话提炼，短引文明确标识并附原文链接，不默认归档或展示整篇转载。注明出处不等同于取得转载或图片授权；来源记录单独保留可核验的许可信息，未知时明确标记。完整原页、抓取缓存若为处理所需，仅留在被忽略的 local-data/work/ 中，不进入公开产物。

## 3. 关键图片

只保留帮助理解论点的图，例如架构图、流程图、关键对比图；默认最多选择 3 张，可按资料需要调整。装饰图、头像、广告不收录。

每图记录原始图片 URL、所属文章 URL、作者或权利人（可确认时）、原图注、中文图注、许可依据和文件摘要。不移除水印、不伪称原创；无明确保留依据时先提供图所在原文链接和中文说明，待用户核对后再归档图片。

实际保留的图写入私有 docs 的 assets/notes/<documentId>/，Markdown 使用相对路径，经授权 API 转内存 Blob URL 展示；默认不热链原站图片。不能下载或许可待核对的图显示说明与原文入口，不阻塞文字概述。图片替换使用新文件名，保留旧快照引用的旧图。

## 4. 数据组织

以下路径相对于私有 docs 数据根，绝不写入站点根 docs/ 或 Pages public/：

```text
content/inbox/<documentId>/index.md    # Agent 收集的草稿，沿用入库约定
content/notes/<documentId>/index.md    # 两种来源统一的正式笔记正文
assets/notes/<documentId>/...
catalog/notes.json
catalog/documents.json
catalog/<现有全文索引路径>
revisions/<documentId>/<revision>.json
operations/notes/<requestId>.json       # 保存幂等凭据，建议新增
```

一篇笔记对应一个永久 documentId、一篇 Markdown 正文、一套 contentRevision 与快照，直接以 documentId 标识列表项，不再增加 noteId、summaryDocumentId、personalDocumentId 或 noteRole。草稿转正式、改名、改标签或移动目录不改变 documentId；两种来源均按同一规则关联评论。

建议 catalog/notes.json 使用 schemaVersion: 1，notes 数组项含 documentId、path、contentRevision、sourceKind（blog / personal）、title、status、tags、created、updated、sources。正文沿用现有数据契约，使用 type: notes，并增加 sourceKind、language 字段；非论文的 paperId 为空。前置元数据和 catalog 同次生成，不能各自手工维护而产生不同值。Blog 的来源信息必填，个人笔记的 sources 可为空；网页修改 Blog 正文不会将其来源变为 personal。

快照仍使用现有规范 AST 和 contentRevision 算法；新增元数据的哪些字段参与版本摘要必须在共享规范中明确，并对旧文档保持兼容。既有论文条目与 schema 不批量重写；新笔记目录作为可选配置接入，旧配置缺少该路径时显示空笔记入口。

Agent 再次整理 Blog 时先读取同一 documentId 的最新正文，生成更新候选和差异，不新建重复笔记，也不直接覆盖人工修订。用户在线增加的理解和修正保留；重叠修改保留双方版本供审阅，确认后再通过统一保存管线更新该文档。生成过程与最近一次编辑者可另记到操作记录或 Git 历史，不用 sourceKind 表示最近编辑者。草稿通过私有草稿列表和独立草稿索引可检索，正式列表默认排除草稿。审核转正式时移动路径但保持 ID。

## 5. 网页 Markdown 编辑

网页“新建笔记”默认 sourceKind: personal：输入标题、标签和 Markdown → 分栏预览 → 选择草稿/正式 → “保存并提交”。这里的总结由用户撰写，当前方案不额外引入网页 AI 总结服务。

所有已有笔记，包括 Codex 创建的 Blog 阅读记录，都提供相同的“编辑”入口：加载最新可编辑版本 → 修改正文、标题、tags 或可编辑的来源信息 → 预览正文和改动差异 → “保存并提交”。Blog 原始出处保持可见，必填来源字段不能被清空；来源信息纠错也记录历史。已发布笔记普通更新默认保留原状态，不因编辑或 Codex 更新候选而自动退回草稿；草稿转正式仍由用户明确选择。

手机切换编辑/预览。工具栏第一版提供标题、列表、链接、代码块、图片上传和撤销重做，支持快捷保存。自动排版、多人实时协作留到后续。

标题和标签在表单中维护；Markdown 编辑区不暴露 documentId、段落标识等内部元数据。预览复用阅读器现有 Markdown 渲染和净化规则；代码、公式、表格显示保持一致，不允许可执行 HTML 或远程脚本。第一版不在编辑预览中新增评论。

页面连接私有 docs 时使用 Contents 读写令牌，因为笔记保存会直接创建 Git commit；同一 PAT 也用于配置中的 comments 私库。PAT 默认留在标签页会话中，用户可选明文存到本机浏览器七天。PAT 需分别授权两个私库的 Contents 读写权限。权限错误会保留编辑内容和本机草稿；评论连接失败不阻止 docs 阅读。

PAT 默认留在标签页会话，用户可选择七天本机浏览器存储，具体规则见 [浏览器直连 GitHub](browser-github-access.md)。令牌不会写入 IndexedDB 草稿、构建产物或日志。为应对浏览器误关闭，草稿存入 IndexedDB：仅保存标题、tags、状态、Markdown、来源 documentId、原始 expected HEAD、时间、待保存图片及待重试请求标识，不保存任何凭据。新建与编辑都自动暂存；重新打开后列出可恢复草稿，用户选择恢复或丢弃，不自动覆盖文档库。恢复保留原 expected HEAD，仍走并发冲突检查；成功保存或用户明确丢弃后清理对应记录。多标签页用独立 ID 和活动租约隔离，写入及删除时原子核对所有者。单草稿上限 24 MB；IndexedDB 被禁用、配额不足或升级受阻时保留页面输入并提示下载 Markdown。关闭时尽力写入，但不承诺操作系统强制终止或设备故障时可恢复。该本机草稿不等于 Git commit，也不取代备份。

## 6. 一次保存对应一次完整 commit

不能只提交 Markdown 后再等待索引修复。浏览器保存使用共享纯函数内容管线生成规范化 Markdown、AST 快照、段落身份、附件摘要、目录与全文索引增量；当前本地入库技能尚未切换为调用该模块，接入前不得声称两者已共用运行时代码。

保存时：

1. 以编辑开始时读取的 docs commit、目标 contentRevision 和元数据摘要作为基线。若从发布版进入编辑，先对比当前目标分支；发现目标文档已有更新，先展示差异再进入编辑。
2. 生成 requestId 和载荷摘要，首次提交时间跨重试保持不变。请求指明目标仓库、分支、documentId、预期版本和改动；路径由受控映射生成。创建时固定 created，后续更新保留 created 并刷新 updated，跨重试复用首次操作时间。
3. 读取 docs HEAD 和已保存的 requestId；已完成的相同请求直接找回对应 commit，载荷不同则拒绝复用。无改动时不创建空提交。
4. 以 HEAD 的完整 tree 为 base_tree，新建本次涉及的正文、图片、快照、目录、搜索分片和幂等记录 blobs；其他文件原样保留。
5. 创建以该 HEAD 为父节点的单个 commit，再以 force: false 更新目标分支。只有分支更新确认成功，才显示“已保存到 Git”与真实 commit 链接。
6. 当前会话从确认提交的固定 SHA 重新加载整套目录、索引、正文与快照，避免最新正文搭配旧索引。评论仍按选定 comments commit 及新正文版本解析。

GitHub 支持 tree/commit/引用更新；更新引用需要相应写权限，非强制更新防止覆盖并发提交。依据：[Git trees](https://docs.github.com/en/rest/git/trees)、[Git commits](https://docs.github.com/en/rest/git/commits)、[Git references](https://docs.github.com/zh/rest/git/refs)。

并发时最多重新读取并重试 3 次：其他笔记变化可基于新 HEAD 重新生成派生数据；同一正文、标签、来源等目标内容变化则停止，展示“原版本 / 我的修改 / 远端版本”，由用户解决。不能仅比较正文摘要而漏掉元数据冲突。网络响应丢失先按 requestId 核验远端结果，不重复提交。分支保护拒绝时保留草稿，说明原因，不强制推送或改规则。

稳定段落 ID 在编辑模型中隐藏维护：原段落移动且文本不变时保留 ID；拆分、合并或替换生成新 ID。身份无法确认时采用新 ID，不凭相似句子复用。更新不得删除旧快照、旧图片或 comments 中的任何记录；旧评论按版本规则转待重新链接。

## 7. 保存与发布分别展示

界面状态至少包含“未保存”“本机草稿已暂存”“提交中”“已保存到 Git”“阅读器版本待同步”“已发布”“保存失败/冲突”。浏览器自动草稿、本地 Git commit、私有 docs 远端同步与公开阅读器发布必须清晰区分；草稿显示“已保存为草稿”，不会因推送成功变为正式。

保存到 docs 后，当前已授权会话可明确切换到最新保存 SHA 继续阅读；重新打开站点默认仍读取公开配置固定的发布版本。建议增加“读取最新私库版本”按钮，显示其与发布版本的区别，不静默将单篇正文切到 HEAD。

正式发布继续遵循 docs/deployment.md：先推送 docs，随后将主库的 docs gitlink、release-manifest.json、site/public/reader-config.json 三个引用同步为同一经过校验的 SHA，推送主库并核验真实 Pages 版本。浏览器 docs 令牌不承担主库写入与工作流权限。

本地演示模式的“同步到 GitHub”入口只说明本地 Git 尚未同步，不发起请求。生产模式直接用“保存到 GitHub”操作写入已授权的私有 docs 分支；它不调用 Pages 或主库发布，也不代表已发布。保存成功后阅读器在当前会话刷新到 notes 分支 HEAD，公开论文版本仍使用固定 release SHA。正式发布继续走既有 docs 与主库发布流程；草稿可以存入私库，但正式筛选仍只显示 published。

## 8. 实施顺序与验收

1. **已实现的工作区**：生产 NotesStore 读取当前 docs 分支，创建和更新笔记、图片、快照及目录/搜索索引采用一次非强制 ref 更新；本地 demo 适配器仍与生产路径隔离。编辑器提供预览、来源卡片、标签与状态筛选、命名空间草稿恢复。
2. **待用户验证**：使用授权测试 PAT 验证私有仓库权限、真实 Contents API、分支保护和保存后刷新；本任务不向真实 docs 写入测试笔记。
3. **仍待实现或确认**：将本地入库流程改为调用浏览器共享的纯内容模块；评论位置迁移与引用快照兼容性验证；历史差异 UI 和自动发布。历史恢复不能重置分支，旧快照保留。

验收至少覆盖：两种来源在笔记列表平铺；来源、tags、状态与全文搜索组合筛选正确；英文 Blog 生成中文概述且来源可追溯；读取失败不编造；有许可依据的关键图经私库显示；Blog 和个人笔记均可网页修改、提交并在重新连接后读取；编辑 Blog 后原始出处和来源类别保留；重新概述不覆盖在线人工修改；更新保留 documentId、created 和默认状态，并刷新 updated、快照与索引；仅正文命中的词可检索并跳转；两标签页编辑相同笔记不会覆盖；保存响应丢失不产生重复提交；旧评论和引用快照完整；草稿与正式状态正确；保存 SHA 与发布 SHA 分开显示；公开产物没有私人正文、标题、图片、索引或令牌。
