# 笔记工作区与离线预览

笔记工作区支持两个隔离的数据适配器。生产页面使用当前标签页填写的私有 `KnowledgeDB-docs` Contents 令牌，在 `main` 分支读取和保存笔记；每次保存以单个非强制 Git 引用更新写入正文、附件、不可变快照、笔记目录、文档目录和全文搜索目录。论文仍使用公开配置固定的 docs commit。生产笔记列表从当前连接的 docs HEAD 读取，论文全局搜索仍使用发布索引，不表示它已经载入最新笔记索引。

本地交互测试使用忽略目录 `local-data/note-demo-git/` 中的独立 Git 库，初始笔记集合为空。它只用于验证编辑、图片和本地 commit，不会上传或导入生产 docs。状态会明确区分“本地 Git · 未同步”和“GitHub docs”；生产端没有额外的假同步按钮。

## 启动本地预览

```sh
npm run dev:notes -- --port 5180
```

打开 `http://127.0.0.1:5180/`。该命令显式启用本地演示接口；普通生产构建不包含这些服务端点。首次启用时只建立空笔记目录，不会创建示例笔记。

## 交互

- 笔记模式提供约 292px 单侧栏，含论文/笔记/专题切换、搜索、新建笔记、来源、状态、标签筛选及平铺列表。来源、状态、搜索条件彼此取交集；多个标签按任意一个匹配（并集）。顶栏按钮可收起为约 56px 图标栏，编辑区随之扩展；折叠不会退出当前编辑。
- 编辑区包含标题、来源/状态/标签、Markdown 工具栏和单一正文区。工具栏支持标题、粗体、斜体、删除线、列表、任务、引用、代码、链接和撤销/重做。默认只显示 Markdown；预览按钮切换到完整渲染，关闭预览后恢复编辑光标和滚动位置。
- 在正文区粘贴或拖入 PNG、JPEG、GIF、WebP 或 AVIF 图片（单张不超过 5 MB），图片会插入光标位置并随笔记保存。图片完成读取后显示“待随笔记保存”；只有保存成功后才进入本地 Git 或远端 Git commit。
- 保存成功后会刷新并选中笔记。若当前来源、状态、搜索条件不匹配，工作区只调整隐藏该笔记的筛选条件；已选标签中任一匹配就保留整组选项，全部不匹配才清空标签。保存不会把草稿状态改为正式。
- Blog 来源卡片保留原始标题、作者、站点、链接和访问时间；编辑保留已存的 Blog 来源元数据。原始来源链接仅允许 `http` 或 `https`。
- 新建和编辑均自动写入浏览器 IndexedDB；刷新或重新打开后，工作区列出可恢复草稿，由用户选择恢复或丢弃，不自动覆盖已保存内容。草稿保留开始编辑时的 HEAD 基线、稳定文档 ID、附件和待重试请求标识；保存仍进行并发校验。草稿库按仓库/分支/适配器命名空间隔离，多标签页以所有权检查避免互相覆盖。
- 本机自动草稿最多 24 MB；浏览器禁用 IndexedDB、空间不足或升级被阻塞时，会提示自动保存不可用并保留当前输入供下载。关闭页面时尽力写入，但不能保证操作系统强制终止或设备故障时一定恢复。草稿不包含令牌。

## 验证流程

1. 启动服务并打开“笔记”，确认空列表与筛选出现；新建笔记并保存，确认条目出现在列表并保持草稿状态。
2. 折叠侧栏，确认只留下图标栏且编辑区占用释放的宽度；展开后确认原笔记和编辑内容仍在。
3. 编辑或新建笔记，测试工具栏和撤销/重做；切换预览再关闭，确认 Markdown、光标和滚动位置保留。
4. 粘贴或拖入合规图片，确认光标处插入 Markdown 引用、预览可见并显示待保存状态；本地保存后刷新确认附件仍可显示。
5. 使用隔离的测试 PAT 验证生产连接和真实 GitHub 保存。令牌不得发给 Agent、写入 IndexedDB、构建产物或日志。不要用生产笔记库测试破坏性操作。

## 边界

本地演示写入仅发生于 `local-data/note-demo-git/`，远端适配器只在真实页面中使用用户当前输入的 docs Contents 读写令牌。生产保存先验证私有仓库、分支和现存 catalog，再通过 Git blobs/tree/commit 及 `force: false` 更新 ref；只有 ref 更新成功才报告保存完成。并发 HEAD、附件路径、requestId 幂等和请求载荷均会校验；失败时保留编辑输入与本机草稿。

笔记版本管线生成 Markdown 元数据、规范化 AST 快照、正文段落身份、附件摘要、文档目录和笔记搜索项，并增量保留现有论文目录和搜索项。尚未实现评论位置迁移或 `annotations/` 写入；不会删除旧快照和旧附件。生产远端 PAT 与真实分支保护行为需要由用户在浏览器中验证。docs commit 不会自动发布 Pages，也不会改变论文固定 release SHA；正式发布仍走既有部署流程。
